# External Algorithm Trajectory Format (Level 2)

[简体中文](./ALGORITHM_TRAJECTORY.md) | [English](./ALGORITHM_TRAJECTORY.en.md)

Level 2 is intended for validating IK or trajectory algorithms that users have already implemented outside RoboStation. RoboStation does not execute algorithm code. It imports numeric results, converts them into an existing `RobotTask`, replays the task, and compares the target TCP poses with the poses actually reached.

## Recommended Workflow

1. Load the URDF that matches the external algorithm in RoboStation.
2. Download the template for the current model from Task Composition.
3. Use Python, C++, MATLAB, ROS, or another tool to calculate joint solutions for the target TCP poses.
4. Preserve the template's `model` and `units` fields, then populate `trajectory` in execution order.
5. Return to Task Composition, import the file, and replay it.
6. Review errors under Validation Results and export a `.simulation.json` or `.trajectory.csv` file.

## File Example

```json
{
  "format": "robostation-algorithm-trajectory",
  "version": 1,
  "generatedAt": "2026-08-20T06:00:00.000Z",
  "name": "Pick trajectory validation",
  "description": "Generated by an external IK solver",
  "units": {
    "revolute": "rad",
    "prismatic": "m",
    "tcpPosition": "m",
    "tcpRotation": "deg-xyz"
  },
  "model": {
    "name": "Fetch",
    "fileName": "robot.urdf",
    "tcpLinkName": "gripper_link",
    "jointSignature": "Preserve the original value from the downloaded template",
    "jointIds": ["torso_lift_joint", "shoulder_pan_joint"]
  },
  "trajectory": [
    {
      "speedScale": 0.5,
      "targetPose": {
        "x": 0.65,
        "y": 0,
        "z": 0.258,
        "rx": 0,
        "ry": 57.296,
        "rz": 0
      },
      "joints": {
        "torso_lift_joint": 0.12,
        "shoulder_pan_joint": 0.35
      }
    }
  ]
}
```

The joint list in this example is shortened to demonstrate the structure. Every trajectory point in an actual file must include all controllable joints listed by the downloaded template.

## Units and Coordinate Conventions

- Revolute and continuous joints: radians.
- Prismatic joints: metres.
- TCP `x / y / z`: metres in the coordinate frame of the current URDF root object.
- TCP `rx / ry / rz`: degrees using XYZ Euler angles, matching the TCP state shown in the interface.
- `speedScale`: from `0.1` to `1`, controlling the existing simulator speed scale. It is not an exact time parameter.

A future real-time IK provider will continue to use the quaternion interface defined in `IK_DESIGN.en.md`. Level 2 files use XYZ Euler angles so imported targets remain consistent with the current workstation display and CSV output. Integrators should convert quaternions to XYZ Euler angles when generating the file.

## Import Validation

RoboStation checks the following before accepting an import:

- File format and version.
- Whether the current TCP link matches the template.
- Whether joint IDs, joint types, and the URDF limit signature match.
- Whether every trajectory point contains the complete joint set and no unknown joints.
- Whether every joint solution is finite and within its URDF limits.
- Whether every TCP pose contains finite numeric values.
- Whether the trajectory contains between 1 and 50 points.

If any check fails, the file is rejected. RoboStation does not pad missing values with zeros, truncate joint values, or generate fabricated IK solutions.

## Validation Output

When the task reaches each trajectory point, the system stores an additional arrival sample and calculates:

- Target coverage: whether an actual arrival sample exists for every target.
- TCP position error: the 3D distance between target and actual positions, with a default threshold of 2 mm.
- TCP orientation error: the rotation angle between the target and actual orientation quaternions, with a default threshold of 1°.

JSON output preserves the target, actual value, and error for every trajectory point. CSV output adds the target TCP pose, position error, orientation error, and a `waypoint_reached` marker to the time-series samples.
