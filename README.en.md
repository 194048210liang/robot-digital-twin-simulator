# RoboStation

**A browser-based robot offline simulation and validation workstation built with Vue 3, TypeScript, Three.js, and URDF.**

[简体中文](./README.md) | [English](./README.en.md) · [Live Demo](https://robot-digital-twin-simulator.l194048210.workers.dev/)

> Current version: V0.2. RoboStation focuses on offline simulation and validation. It does not connect to physical hardware or send simulation tasks directly to a real robot.

## Overview

RoboStation is more than a URDF model viewer. It provides a complete browser-based workflow around the model, pose, task, execution, sampling, validation, and export stages of robot development:

```text
URDF / Mesh
     ↓
Joint Teaching or External Algorithm Results
     ↓
Robot Task Composition
     ↓
Simulation and TCP Trajectory Sampling
     ↓
Limit, Continuity, and TCP Error Validation
     ↓
JSON / CSV Export
```

The repository includes a Fetch mobile manipulator as its default example. It also supports local URDF packages with mesh and texture assets, then derives controllable joints, limits, and display units from the imported model.

## Why RoboStation

- **Model-agnostic input**: load a local URDF package and extract controllable joints, joint types, limits, velocities, and the end-effector link.
- **Visual joint teaching**: drive the 3D model in real time, combine multiple poses, and save them as replayable robot tasks.
- **External algorithm validation**: import target TCP poses together with complete joint solutions generated by your own IK or trajectory code, without executing external code in the browser.
- **Traceable simulation output**: record joint positions, targets, velocities, and TCP poses over time, then export structured JSON and CSV data.
- **Explicit engineering boundaries**: keep Three.js rendering, robot control, mock communication, task state, and validation rules decoupled so solvers and transports can be replaced later.

## Features

### Models and 3D Scene

- Built-in Fetch example model.
- Local URDF import with STL, DAE, texture, and related assets.
- Automatic parsing of revolute, continuous, and prismatic controllable joints.
- Camera fitting based on model bounds, orbit controls, grid, fullscreen mode, and screenshots.
- Live TCP frame visualization and actual TCP trajectory rendering.

### Teaching and Tasks

- Joint sliders update the 3D model in real time.
- Joint limits, speed scaling, and home-position control.
- Single-joint control and batch joint target editing.
- Multi-pose task composition, local persistence, sequential playback, pause, resume, and stop.
- Model-bound `.robot-task.json` import and export with a joint signature.

### External Algorithm Results — Level 2

- Download a model-specific result template for the currently loaded URDF.
- Import target TCP poses and complete joint solutions produced by an external IK or trajectory algorithm.
- Validate the TCP link, complete joint set, joint types, URDF limits, and numeric values.
- Convert a valid result into the existing `RobotTask` format and replay it through the original controller and simulator pipeline.
- Compare every target TCP pose with the actual reached TCP pose, including coverage, maximum position error, and maximum orientation error.
- Read numeric results only; uploaded scripts, libraries, and algorithm code are never executed.

### Simulation Validation and Export

- Automatically sample joint and TCP states during task execution.
- Validate task completion, joint position limits, joint velocity limits, and sample continuity.
- Add TCP target coverage, position error, and orientation error checks for externally generated tasks.
- Preserve the model, task, samples, metrics, and final validation result in each record.

## Inputs and Outputs

| Type                      | Format                       | Purpose                                                             |
| ------------------------- | ---------------------------- | ------------------------------------------------------------------- |
| Robot model               | `.urdf` + meshes / textures  | Build the robot joint tree and 3D scene                             |
| Robot task                | `.robot-task.json`           | Store or transfer a sequence of joint poses                         |
| External algorithm result | `.algorithm-trajectory.json` | Import target TCP poses, complete joint solutions, and speed scales |
| Simulation record         | `.simulation.json`           | Store the model, task, samples, errors, and validation result       |
| Trajectory data           | `.trajectory.csv`            | Export time-series joint, TCP, target, and tracking-error data      |

See [External Algorithm Trajectory Format](./docs/ALGORITHM_TRAJECTORY.md) for the current schema, units, and validation rules. The linked specification is currently maintained in Chinese; an English protocol document can be added when the format is finalized.

## Interface Layout

RoboStation uses a desktop workstation-style industrial HMI instead of a conventional web admin layout:

- Left: Three.js / URDF 3D scene.
- Right: joint teaching, TCP state, task composition, and validation results.
- Bottom: simulation events, validation records, communication diagnostics, and data export.
- Top: model, joint count, TCP link, sampling, FPS, and motion status.

## Architecture

```text
Vue HMI
   │
   ▼
RobotController ──► MockTransport (replaceable)
   │
   ▼
RobotSimulator ──► Pinia RobotState ──► Three.js / URDF
   │
   ├─────────────► RobotTask
   │
   └─────────────► SimulationValidation ──► JSON / CSV
```

Pinia stores serializable robot, task, sampling, and UI state only. Three.js objects remain inside the scene layer. `RobotTransport` isolates communication concerns, allowing the current product to focus on offline validation without preventing future WebSocket gateways or real controller adapters.

## Current Boundaries

Validation currently relies on URDF kinematics and browser-side simulation data. The project does not yet include:

- A built-in general-purpose IK solver or fabricated inverse-kinematics results.
- Collision detection, dynamics, torque, or acceleration analysis.
- Singularity, reachability, or real controller following-error validation.
- Exact time parameterization or real-time control-cycle guarantees.
- A controller protocol that can be sent to real hardware without adaptation.

Exported tasks and trajectories are simulation and algorithm-validation data. They must not bypass a robot controller, safety system, or on-site validation before use with physical equipment.

## Roadmap

- **V0.2**: general URDF import, joint-space tasks, external algorithm result import, simulation sampling, and a JSON / CSV validation loop.
- **V0.3**: integrate a real IK provider and add TCP target solving with candidate-solution previews; no fake IK.
- **V0.4**: collision checking, trajectory charts, extended validation rules, and reproducible demonstration scenarios.
- **V1.0**: a stable model, task, and validation-report workflow, with real-device protocol adapters remaining optional.
